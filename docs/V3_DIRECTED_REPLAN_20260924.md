# V3 难目标与昂贵连接驱动重建

日期：2026-09-24。用户已要求继续完成第三处。本次在前两处多路径补全、动态筛选和时间搜索基础上接通定向重建，默认 `replan_enabled=true`。此前暂停约定属于历史阶段，见 [V3_CONSTRUCTION_20260923.md](V3_CONSTRUCTION_20260923.md)。

## 1. 实施范围与论文关系

借鉴 CEA 的 TAS/SRS 思路：尾部追加困难目标，或退回真实轨迹的较早位置，将受影响的已访目标与未完成目标共同放回构造过程。完整可行工作解则优先围绕昂贵脉冲重建，同时保留原有随机结构变异。

本实现适配单飞行器、自由飞越和 J2 动力学，不是 CEA 原算法复现。没有移植交会速度匹配、燃料硬上限、原论文时间目标或 GA 分配层；没有建立目标对/片段预处理库。完整候选的初轨、全机动表、任务时间和访问计划仍交给既有全任务联合优化。

## 2. 重建过程

`v3ReplanProbe` 固定输入脉冲连续传播一次，并在已知见证和提案时刻检查目标位置，保留轨迹插值解及逐弧高度结果。此诊断把物理见证与计划时刻距离分开：旧时刻已经飞越，不能证明新访问安排已实现。没有确认的见证只是搜索线索，不是“全任务不存在其他接近事件”的证明。

入口选择包括：

- 计划超差或未确认目标：回退到对应事件之前的脉冲，并可进一步回退一个脉冲。
- 尾部仍有时间：追加构造作为备选，不占据所有重建尝试。
- 全部目标有见证：按实际脉冲模长排序选择重建位置。
- 高度失败：优先回到首个不安全弧之前；传播失败可从原初轨重新构造。
- 起始历元作为广域备选。同一物理输入重复尝试时轮转入口，避免固定卡在第一处。

`v3PrefixNode` 复用上述同一次连续传播，在截断处取脉冲前状态。仅保留此前脉冲和已有物理见证；截断处及之后尚需访问的目标重新开放。不会写入目标位置、目标速度或原后缀边界状态。

随后由已有时间搜索和多路径束生成新前缀。该专用调用使用 `v3Complete(...,false)` 的提案模式，逐动作仍检查真实传播和高度，但不对每个初猜重复执行整条长前缀的双积分扫描。输出明确标记 `proposal_pending_full_recovery`，`completion_check.passed=false`；主搜索普通前缀筛选默认保持开启。

新前缀未覆盖全部目标时，保留新前缀结束时刻之后的原后缀脉冲，组成待联合恢复的完整时间表。这只是继承控制初猜：后缀必须从新的真实状态传播，没有重置到旧状态。新前缀已覆盖全部目标时可截短任务、删除冗余后缀，包括任务终点处的无用脉冲。

每个提案始终携带 `target_ids=1:35` 和完整 `visit_plan_times_s`。新前缀外的旧见证不自动继承为有效访问。计划时刻只是初猜，联合优化仍可改变；局部少用脉冲或构造覆盖多不等于全任务省油。

## 3. 主循环与失败处理

- 已独立验证的工作解完成首次精修后，以默认 0.5 概率进入定向重建，其他机会仍使用原随机结构变异。
- 普通恢复重试维持原轨迹、完整任务目标集和父解。停滞达到门槛后进入独立 `replan_queue`。
- 停滞前缀在删除谱系前先进入重建队列，经恢复来源调度，避免在每次束构造后额外占用一轮重建预算。
- 普通恢复与重建请求按恢复来源尝试次数交替，失败也推进调度。一次重建无提案可排队重试，默认至多 3 次；达到算法门槛的输入记入 `replanned_keys`。
- 每个入口分别捕获失败，记录原因，并在预算允许时继续后续入口。阶段预算耗尽后不启动下一阶段；已经生成的提案仍保留。
- 多个提案共享原父工作解，第一个交联合求解，其余进入恢复池。预算边界保留尚未处理的提案。SA 使用该原父解的完整成本，不能替换成别的工作解。

候选必须先通过全部 35 目标的联合恢复，再通过固定原脉冲独立复核，才允许进入工作池和 SA。返回原父轨迹不算新接受。独立验收继续检查全目标距离、全程高度、任务时间与初轨，导出规则没有放宽。

## 4. 参数、记录与限制

| 配置 | 默认值 | 含义 |
|---|---:|---|
| replan_enabled | true | 启用定向重建入口 |
| replan_probability | 0.5 | 工作解精修后的重建选择概率 |
| replan_seconds | 8 s | 单次重建软预算 |
| replan_cut_count | 2 | 每次选择的入口上限 |
| replan_retry_limit | 3 | 无产出恢复请求重试门槛 |

这些都是可配置搜索近似，不是比赛约束。有限入口、有限束宽、见证探测、优先目标加权、停止次数都可能遗漏更好结构；并不宣称全空间穷尽、严格下界或全局最优。单次积分、事件扫描及必要独立复核仍可能造成软超时。

`replan_history` 记录输入轨迹键、尝试次数、父轨迹键/成本、重点目标、可选与选定入口、放回目标集、每个入口结果及分阶段耗时。`replan_origin` 随候选保留模式、截断时刻和新前缀结束时刻；联合记录可追踪来自哪个重建。检查点 schema 为 `free_maneuver_search_v3_5`，同时校验源码 SHA-256；旧签名检查点不能直接恢复。
