## 2. 代码层面的原因

1. **提案只瞄准单个目标。** `crossing.m` 每个提案对应一个穿越事件；`v3GuidedTransfer` 把终点修正到该目标 0.05 km 以内。第二个目标只有在新弧恰好从 1 km 内经过时才计入，属于巧合。
2. **子节点在到达时截止。** `expand.m` 令 `child.T = seed.arrival`。到达后自然弧上的后续相遇不属于这条边；下一次扩展默认再施加一次新脉冲。零脉冲滑行子节点只在没有任何转移子节点时才生成（`expand.m` 第 78 行），而且滑行固定时长，不瞄准相遇。
3. **回溯阶段根本不调用 absorb。** `run_v4_incumbent_pilot.m` 第二阶段只调用 `expand`；absorb 只存在于第一阶段的 `search.m`（第 65–72 行）。这是我在实施回溯入口时的遗漏：三步改进中已有的“一次脉冲两个目标”能力没有接入新的主搜索。
4. **absorb 的候选门槛用错了量。** 它要求沿当前弧的弹道延伸在 48 h 内穿越目标面时距离目标 ≤2000 km（`absorb_miss_km`），且只取 3 个候选。不同轨道半径的目标在穿越点通常相距数千千米，即使只需很小的脉冲修正也会被这一门槛挡掉。决定能否便宜地并入的应是修正所需的额外 ΔV，而 absorb 已有的线性预筛正好能算这个量，却放在门槛之后。
5. **能力范围很窄。** absorb 只改最后一次脉冲的矢量和时刻，只加 1 个目标，而且只能在已有单目标子节点之后作为补救运行；没有“同时瞄准 j 和 n”的提案类型。
6. **排序不认识多目标价值。** 回溯按“访问数优先、再比 ΔV 与罚项”排序子节点，逻辑上会优先多访问子节点，但因为生成端从不产出，这一偏好从未起作用。

## 3. 影响

- V4 模型的核心思想——多个目标共享自然弧——在目前的主搜索（定界回溯）中完全没有作用，第一阶段也只偶尔发生。
- 此前在 19.18 km/s 链前缀上的离线检验（`eval_v4_absorb`）中，成功吸收的额外成本只有 +0.010 到 +0.150 km/s，而单独去一趟同一目标的最低提案成本是 0.91 到 6.39 km/s。每次成功合并可以省下一整段腿的成本；机会一旦出现价值很大。
- 队友热启动 20 分钟没能改进 9.99 km/s，新分支从未一次增加两个访问，可能是原因之一；但前缀深度、采样宽度等因素没有隔离，不能据此归因。

## 4. 改进方向（未实施，待用户决定）

1. **把 absorb 接入回溯阶段。** 对每个新入树的转移子节点调用 absorb，成功结果作为同一父节点下的额外子节点（它只改最后一次脉冲，前缀不变，符合现有前缀断言）；受现任界约束，并计入扩展时间。absorb 在无候选时约 0.1 s、完成修正时约 0.6 s，可以先只对将要下潜的子节点调用。
2. **用额外 ΔV 代替距离门槛。** 对窗口内全部穿越事件做线性预筛（一次变分积分加每事件一个 6×6 求解），按预测额外 ΔV 与线性残差排序，再对前几名做牛顿修正。借鉴依据仍是 Xia 等 2022（单脉冲双目标以牛顿法求根）和朱阅訸论文 6.4 节“试射+微调”。
3. **新增双目标提案类型。** 在 `crossing.m` 中对“先到 j、随后自然穿越 n”的事件对直接求一次脉冲同时满足两个相遇，而不是先生成单目标子节点再补救。
4. **排序兼顾每 ΔV 访问数。** 现任界存在时，比较“每单位额外 ΔV 增加的访问数”，让便宜的双目标子节点优先下潜。

建议先做只读核对：在已保存节点上对窗口内全部事件计算预测额外 ΔV，看低于 0.3 km/s 的候选有多少被 2000 km 门槛挡掉。这一步决定方向 2 是否值得；之后再做 1，最后做 3。
