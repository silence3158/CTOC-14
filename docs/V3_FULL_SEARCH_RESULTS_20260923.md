## 代码层原因

1. `v3Search` 只对 fresh 来源执行精修输入去重，work/joint_refine 会在同一完整解上反复重启相同子问题。工作池去重解决的是存储重复，并未解决计算重复。
2. `v3SparseFuel` 用辅助节点残差和罚函数接受下降步，严格 best 门槛是 1e-10；稍宽的 raw 提案交给全程物理回溯。局部缺陷到全程误差的放大使较低辅助目标不能直接兑现为可行下降。原日志没有保存每个失败回溯的距离/高度，因此不能仅凭原日志区分具体失败分量。
3. 物理回溯列表虽有 7 档，预算实际只够尝试前 1–2 档。计算时间主要用于反复生成相同提案，未为完整验收和后续一致性修正保留足够机会。
4. 全局变异直接大幅改时刻/脉冲后依赖恢复器挽救，当前恢复效果不足。模型允许跨区域，候选生成和恢复机制尚不能高效实现这种跨越。
5. 信息素只在刷新导出精英且 proposal_keys 非空时沉积；外部初猜和工作解路径无键，束路径又未完成全任务，导致本轮一直为空。不能把这轮叫作已经发挥了蚁群学习优势。

## 下一步优先顺序（尚未实施）

1. 为下降步增加全任务动力学一致性修正/缺陷收敛过程，随后固定原脉冲独立验收；保留所有联合变量，不能用目标位置重置来掩盖误差。保存每个物理回溯的访问数、距离、真实成本与高度。
2. 缓存同一物理轨迹的精修尝试和数值状态，允许续算或明确改变策略，避免无变化地从头重复。按物理轨迹而非 witness 字段计新增候选；equal-cost 原解保底不计有效搜索接受。
3. 将大变异改为带连接条件的轨迹提案，再进入全任务联合修复；候选构造的局部性不应锁死最终初轨、时刻或后缀。
4. 建立合法完整轨迹的状态动作归因，使信息素能获得有依据的反馈；不能用局部便宜或虚假全访问奖励替代完整任务质量。

本轮足以说明当前求解实现低效，不能说明原模型无可行优解或已陷入数学局部最优。暂不建议重复相同配置或扩大批次。先由开发侧验收一次真实完整任务的下降及一次不同物理轨迹的可行恢复，再让用户运行长实验。
