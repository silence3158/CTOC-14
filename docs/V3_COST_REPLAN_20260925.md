# V3 成本驱动重建改进

用户 2026-09-25 恢复工作并要求持续改进至真实冷启动完整独立 J2 成本低于 6.1 km/s，或用户要求停止。本记录不表示目标已经达成。历史最佳可诊断但不得作为新搜索初猜；正式 24 分钟批次及 ATK 不启动。

## 第一轮改动

- `v3CostReplanCuts` 从累计耗油选择更早切点，所有成本重建保留前缀须小于 6.1 km/s。按访问进度的预算引导及 25%、50%、75%、90% 成本切点只用于生成提案，不是物理下界或严格剪枝证明；保留从零重建机会。
- 超限联合输出以及被拒绝的新前缀直接进入重建队列，完整恢复目标仍为全部 35 个。无合格工作解时增加恢复来源机会，防止反复只造新前缀。
- 成本驱动重建使用尾部补全，不因输入已经有 35 个访问而关闭该能力。新提案若未完成，仅保留实际新前缀，随后从真实状态继续补齐；不拼接旧父后缀脉冲，也不恢复旧访问见证。
- 此轮源码接口 v3_11；真实测试 `v3_cost_replan_cold_300_seed888_01`，空历史输入、seed 888，名义300秒、实际300.978秒。最高24/35、10.6273671 km/s，**无完整解，测试未达标**。两次成本前移重建已执行，保留前缀成本分别1.478364和2.963695 km/s；9个重建提案，无完整联合调用。不能把重建入口执行等同降成本成功。

方法关系：沿用已核对 CEA TAS/SRS 的尾部追加和前缀释放重建；预算切点是本题成本门槛下的改编，不是论文原公式。没有改变正式目标、自由度和全任务验收。

## 待验证的效率改动

已阅读 lamberthub `universal_solvers/izzo.py` 的 `_find_xy`：`M_max=floor(T/pi)`，其中 `T=sqrt(2*mu/s^3)*tof`，`s=(r1+r2+chord)/2`。与椭圆通过两端的最小半长轴 `a_min=s/2`、最短轨道周期一致。来源：https://github.com/jorgepiloto/lamberthub/blob/main/src/lamberthub/universal_solvers/izzo.py ，参考 Izzo (2015), Revisiting Lambert's problem。

第二轮已将必要圈数上界用于已有 MATLAB Lambert 种子枚举，保留原求解器和所有真实 J2 验收，不引入 Python 运行依赖。`check_v3_lambert_bound` 对27组端点几何/时长核对，保留全部宽枚举分支及出发速度，尝试的多圈区间从162降至52。不能用它限制 J2 全部轨迹空间。当前网络系统证书校验失败，公开源码使用单次 curl `-k` 读取，没有改全局 TLS 设置或执行下载代码。

第二轮还修正主循环只给单个补全候选更新前缀经验的问题：全部检查通过的候选按既有有限种群规则进入反馈，不给超限候选正奖励。同族仍合并，不是每个副本重复沉积。成本重建的实际新节点回到外层束继续构造；提案仍未认证，后续一致性与全任务独立验收不可省略。源码接口 v3_12；空输入真实测试 `v3_cost_replan_cold_300_seed888_02` 实际303.282秒，独立完整35/35、22.1574873 km/s，按门槛拒绝。未优于此前18.34记录，更未达到6.1。2次成本前移重建，1次完整联合、1次前缀联合、无工作变异；不得将此次提速写成成本改进。
