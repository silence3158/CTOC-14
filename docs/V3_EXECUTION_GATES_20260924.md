# V3 动作预算、精修记录与验证标签修复

日期：2026-09-24。接续 `V3_SCHEDULING_TASK_IDENTITY_20260924.md`，处理该次静态审查剩余三项。正式物理模型、全任务目标和独立验收条件不变。

## 1. 引导动作机会与成功分支保留

此前 `v3Expand` 固定先自然滑行、再随机脉冲、最后引导，前两项可能耗尽节点预算。引导时间搜索即使已得到多个成功分支，扩展层仍重新积分，并在预算到点时直接停止处理后续分支。

现在每次扩展用保存于检查点的 RNG 随机排列前三个基础动作族，后续动作仍按信息素与探索概率抽样。引导时间搜索按剩余动作槽数分配剩余预算，避免单次时间精修默认占用几乎全部余额。记录 `action_order`、`attempted_kinds`、实际耗时和软超时。随机排序消除了固定顺序的系统性偏置，但有限墙钟预算不保证每次扩展都能执行三个动作；长积分仍是不可抢占操作。

`v3GuidedTransfer` 在分支枚举、修正迭代及回溯积分开始前检查预算，成功分支同时返回本次实际积分弧与高度检查。`v3TimeSearch` 在每批分支返回时扫描实际访问，将耗时计入后续时间搜索的可用预算，并缓存扫描结果；到点时只完成已积分的当前分支批次，不再新增时间试探。`v3GuidedChildren` 整理全部成功分支后，再按 `guided_keep` 和既有束多样性规则裁剪；不因已到预算而丢弃尚未整理的成功分支。失败仍逐项归档。记录 `guided_actions`、`guided_processed` 和 `reused_arcs`，区分已成功求解、已处理和束裁剪。

复用弧必须与当前真实脉冲后状态、出发时刻和终止时刻匹配，不可借用其他入口的弧或重置状态。成功弧的整理不再重复积分或额外传播未来估价弧；该路径使用终点当前目标位置差/前瞻时长构造廉价剩余成本估价。普通动作保留原未来状态估价。两者均为搜索排序近似，不是成本下界或物理可行性证明。最终完整任务独立验收照常执行。

成功分支的访问扫描和束裁剪允许形成软超时，完整记录耗时；预算耗尽后不继续生成新的动作或修正迭代。保留已完成工作不等于突破 `guided_keep` 的配置上限，也不代表搜索覆盖所有分支。

## 2. 精修记录依据实际工作

`v3Search` 不再在调用联合优化器之前写入 `refined_keys`。联合优化器现在报告 `refinement_performed`，只有发生有效求解工作才记录输入物理轨迹为已精修：

- 恢复及稀疏 SQP：实际子问题迭代、明确求解结束，或评价了有限的试探步；只完成初值评价不算。
- 常规 SQP：实际迭代或明确求解结束；仅启动回调不算。
- 投影求解：QP 实际迭代、明确求解结束，或连接完成的物理提案；只有打靶问题构建不算。

明确求解结束包括成功退出，以及求解器 `exitflag=-2` 报告当前局部子问题不可行。这不证明完整轨迹问题不可行，但说明该次精修确实做过求解，允许后续切换到结构搜索；否则会反复精修同一局部不可行输入。进入求解前已耗尽预算仍不计。原始退出状态、步评价数及物理验收分别保留。

这表示该轨迹获得过实质求解机会，不表示成本改善、完整可行或数学最优。保底原解仍按原来源报告。零步调用不会让工作池下一次直接跳过精修进入变异，也不会让相同 fresh 输入被永久去重。稀疏 SQP 的 `output.iterations` 同时改为实际完成的 QP 调用数，避免循环入口的索引 1 冒充一次迭代。

## 3. 验证标签跟随选中的复核结果

`v3ProjectedJoint` 返回轨迹的 `validation_level` 取自最终选中轨迹的 `info.replay.validation_level`。仅筛查通过的保底输入保持 `nominal_j2_screened`；即使输入曾带有独立通过标签，也不能在当前实际检查不足时照搬。当前调用已独立重放通过的保底解，以及通过 `v3Verify` 后接受的新解，才保留相应的独立通过标签。

这次未放宽工作池、SA 或精英导出的全任务独立验证入口，也未提升 `official_alignment_verified=false`。
