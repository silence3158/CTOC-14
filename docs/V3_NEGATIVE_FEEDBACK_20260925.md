# V3 负反馈分辨力与归因修订（A1/A2）

日期：2026-09-25。本轮只改**搜索内部的负反馈语义**，不改正式物理条件、不改 6.1 km/s 接纳门槛、不改验收层级。目标：让"罚得贵"这件事在搜索里**可区分**，并把惩罚归因到真正造成超支的机动。用户验收目标为"真实冷启动、完整 35/35 独立 J2 通过、原始总 ΔV < 8 km/s、路径正确且可复现"。

## 2. A1：罚分单调化（不再被削平）

### 2.1 倾角罚

```text
旧: penalty = ((Δi-5)/5)^2                 → 任何 Δi>5° 都被 min(4,·) 削平
新: penalty = L·x/(x+C·5),  x=max(0,Δi-5), L=plane_penalty_saturation(默认2), C=L-1
```

固定点（`plane_penalty_saturation=2`）：5°→0，10°→1.0（与旧式重合），45°→1.73，90°→1.82，渐近于 2.0。

### 2.2 代价罚

```text
旧: penalty += excess/6.1 * share          → 20 km/s 与 31 km/s 均得 4.0（完全无分辨力）
新: penalty += excess/6.1 * share * credit → 单调、可分级，且只在超支时收取
share  = |dv| / 完整候选真实成本
credit = 0                       若该机动与本次消耗后仍在预算内
         1                       若正是这次机动跨过门槛
         |dv| / 本次消耗          若门槛早已跨过（超支后段）
```

要点：`penalty` 是**存储量**，随严重程度单调上升；查询层 `/(1+p)` 再把它转成"越贵权重越低"。这两级方向必须一致——本轮第一版实现把方向搞反了（存的越贵、权重越大），已在检查中固化。

### 2.3 一致性护栏

`v3PolicyFeedback` 新增断言：`rejectedCost` 必须是**包含本次机动的完整候选成本**。传前缀成本会静默颠倒严重程度排序，现在直接报错。

## 3. 定向检查

`scripts/check_v3_policy.m` 扩展为 17 项断言，覆盖：

- 倾角罚在 [5.5, 6, 8, 10, 15, 20, 30, 45, 90]° 上严格递增且恒小于饱和值；5° 处仍精确为 0；10° 处落在旧标度内；
- 代价罚：仍在预算内 → 0 罚；跨界机动 → 满 credit；超支后段 → 小 credit；超支越大罚越重；
- 完整候选路径（`rejectedCost`）与隐式完整路径都能拿到代价罚；
- 同一状态-动作-成本重复观察不重复加罚；
- 一致性护栏会拒绝"前缀成本冒充完整成本"。

结果：`POLICY_CHECK ... passed`（exit 0）。

## 5. 本轮暴露并修正的问题

1. **测试夹具错**：用 90° 倾角轨道绕 y 轴燃烧（只改升交点，不改倾角）→ 罚分恒 0；应沿轨道法向（近赤道轨道用 ±z）燃烧。
2. **测试夹具错**：`[0 0 f(vec)]` 只产生单列，无法向量化。
3. **测试夹具错**：把 `node.J + |dv|` 恰好压在 6.1 门槛上（浮点差 4e-16）导致分支不可判定；夹具改为留明确余量。
4. **测试描述错**：分级规则下"超支后段的机动"本来就应拿到按份额的小罚，旧断言要求它为 0 是错的。
5. **真实缺陷（已在实现中修正）**：负反馈在权重空间方向相反（见 2.2）。
6. **真实约束（已加护栏）**：`rejectedCost` 语义必须是完整候选成本。

### 6.1 诊断（只读脚本 `scripts/report_v3_round_diag.m`）

- **枚举效率是当前第一瓶颈**：时间候选查询 111651、Lambert 调用 112006，但枚举阶段实际传播只有 **306** 次；自然窗口计数 8095 而时间精修只有 759 次改善。大量枚举没有转化为候选质量。
- **深覆盖根缺失**：19 次构造的终端覆盖只有 4–17/35，8 次完整构造停在 8–12/35；完整联合优化总共只被调用 3 次，且全是前缀级（`prefix_restored`）。
- **工作池始终为空** → 变异与 SA 在本轮从未运行，"集束蚁群 + SA"闭环未参与。
- **积压 28 个待处理任务**（fresh 16 + recovery 8 + replan 4），说明构造产出速度远超消费速度，预算被构造与重建吃掉。
- 负反馈命中 42 次（`_08` 为 524 次）。次数下降本身不能判断好坏：新规则只对真正跨过门槛的机动给满 credit，且 `policy_rejections` 只有 8 条；本轮证据不足以判断新罚分是否改善了选择，需要与"枚举效率"解耦后再评估。

### 6.2 由此确定的下一轮优先级（替代原计划）

1. **降低枚举成本、提高每次枚举的转化率**（112k Lambert 调用 vs 306 次传播）：这是当前最可能改变结果量级的一项。研究先行后实施。
2. **让完整联合优化拿到时间**：当前 300 s 里构造+完整构造+重建占 219.6 s，联合只有 3 次前缀级调用；需要在不放弃修复算子的前提下给出配额。
3. 之后再回到 A3（拱点特征）与 B3（修复成功正经验复用）。
