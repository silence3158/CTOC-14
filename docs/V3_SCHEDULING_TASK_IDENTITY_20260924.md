# V3 前缀调度与恢复任务身份修复

日期：2026-09-24。范围仅为静态审查的前两项：默认前缀调度饥饿，以及不同访问计划被错误去重。不改变 V3 物理模型、联合目标或独立验收条件。

## 1. 前缀调度

此前来源轮转与前缀精修同时使用全局轮数取模。当工作池和恢复池持续非空时，来源循环为 fresh/work/recovery/work/fresh/work；默认 `prefix_joint_every=3` 所允许的轮次均被其他来源占用，新前缀持续延期。

`v3BeginAttempt` 现在为每种来源记录独立的 `source_attempt`。前缀精修频率按 fresh 自身的尝试序号判断，失败和延期仍推进计数；来源选择规则保持原语义。上述持续繁忙情况下，第 7、17 轮分别对应第 3、6 次 fresh 尝试，可以进入前缀联合求解。检查点从 `source_history` 保留并重建该序号，不因恢复运行而重新归零。

## 2. 恢复任务身份

新增 `v3RecoveryKey`，用于候选队列、恢复队列、重建完成记录及重建尝试计数。包含：

- 实际初轨、任务时长与脉冲表的物理键。
- 排序后的活动目标集合。
- 是否存在显式 `visit_plan_times_s`，以及活动目标对应的计划时刻；没有显式计划时使用实际见证作为初始化时刻，保留 NaN。
- 存在父工作解时，包含父轨迹的物理键，避免把不同 SA 比较来源合并。

显式计划一致时，重新定位的实际见证不改变恢复任务身份。不同显式计划即使物理脉冲表相同，也会分别保留；同任务重复入队仍去重。一个计划的重建完成记录不能阻止另一个计划入队，也不能提前消耗它的重试次数。

信息素、轨迹族和物理新颖性判断继续使用原物理键；仅变更访问计划不获得重复物理收益。
