## 1. 结论摘要

1. 论文与代码解决的是**「给定访问顺序」下的多飞越轨迹全局优化**，不是顺序搜索。代码里的顺序直接硬编码为 GTOC4 冠军解（`GTOC4_Problem.cpp:173-207`）。CTOC14 的访问顺序本身是自由决策，因此**不能把这篇论文当作解题主算法直接套用**。
2. 论文的核心可迁移物是一个**两脉冲状态降维 + Bellman 支配剪枝的历元动态规划**：状态只保留 `(上一个飞越历元 t_last, 当前飞越历元 t)`，同一 `(t_last, t)` 只保留累计 ΔV 最小的状态。这在给定顺序、且脉冲只允许在飞越历元施加的两体 Lambert 模型下给出**离散历元网格上的全局最优解**，并附带误差上界 `J(P2) ≤ J(P0) + N·ε_max`（式 33）。
3. 这条路线对本项目的价值在于：**把「给定顺序下的时刻安排」从随机搜索变成一个可证明最优的子问题求解器**，用来替换/校正 V3 目前靠随机时间采样与投影修正的时序层。当前 V3 的真实冷启动记录仍在 15–30/35、5.9–22.7 km/s 前缀徘徊（见 `V3_COST_REPLAN_20260925.md`），时序质量是最可疑的瓶颈之一。
4. 但代码**明确不等同于论文**：两体中心引力、无 J2；时间网格以 GTOC4 冠军解为中心生成；GTOC4 专属的「首段 4 km/s 免费 C3」与「末段交会」写死在代价函数里；`check_t` 硬性要求相邻飞越间隔 ∈ [1 天, 1 年]。这些都必须重写，不能照搬。
5. 数量级估算（我的分析，非实验）：在 GEO/MEO 半径、数小时的单段转移上，二体 Lambert 相对 J2 真实传播的位置偏差约 3–20 km（远大于 1 km 判据），但折算到单段脉冲只有 0.1–0.7 m/s，36 段合计约 10–25 m/s，相对 6 km/s 量级约 0.4%。**结论：二体 DP 的成本可作为 J2 真实成本的良好代理，但每段仍必须做 J2 微分修正与独立复核，不能把 DP 输出当可行解。**
6. 本机实测（`tmp/bench`，见 §7）：已入库的 Izzo/Gooding Lambert 单次调用约 6.4 µs。按论文的 `O(Nt³N)` 最坏界，`Nt=100`、35 段约 3.6e7 次调用 ≈ 4 分钟；配合代码里的「管道自适应细化」（每层网格点数恒定、步长逐层减半），完整求解在 MATLAB 内是**量级可行**的。
7. 建议：**先做最小可用验证**（固定一条现有访问顺序 → 两体 DP 求最优历元 → 逐段 J2 微分修正 → 与原脉冲独立验收对比），用一个可判别的问题回答「我们的成本是否主要败在时序上」。在结论出来前不投入完整实现。

## 3. 论文核心内容

### 3.1 问题重构链条

- **P0**：含内点等式约束的最优控制问题。目标为燃料/ΔV，动力学通用（脉冲或连续推力），约束是飞越条件——在每个飞越历元航天器位置与目标位置重合（式 5-7），**不对速度作要求**；飞越历元单调（式 8）。
- **P1**：多阶段决策问题。利用内点约束的 Markov 性质，把每段转移代价 `g_k(s_k, d_k)` 定义为内层无中间约束的最优控制问题（式 9），外层求 `min Σ g_k`（式 10）。状态 `s_k = [t_k; v_k; m_k]`。
- **P2**：离散化 + 近似。`g̃_k = g_k + ε_k`，状态只能取离散值，转移含舍入误差 `θ_k`。
- **P3**：为证明引入的带随机变量版本 `min max Σ g̃_k`（式 17）。

### 3.2 全局最优性（Proposition 1）

对 P3 用 Bellman 递推（式 18）：

```text
J_k^DP(s_k) = min_{d_k} max_{w_k} [ g̃_k(s_k, d_k, w_k) + J_{k+1}^DP(d_k + θ_k(w_k)) ]，J_{N+1}^DP = 0
```

用随机最优控制的 min-max 交换引理做归纳，得 `J*(s1) = J_1^DP(s1)`。由于 P1、P2 的解空间都是 P3 的子集，误差上界（式 33）为

```text
J_1[P2](s1) ≤ J_1[P1](s1) + N·ε_max = J_1[P0](s1) + N·ε_max
```

即：**最终解与原始问题全局最优的差距不超过 N 倍的单段最大近似误差**。论文明确指出该上界是理论值、实际罕见最坏情况。

### 3.3 两脉冲专用解与复杂度

- 一般脉冲/低推力：状态含速度（低推力还有质量），每阶段状态数 `Ns = Nt·Nv³·Nm`，复杂度 ≈ `Ns²N` —— 「维数灾难」（论文举例 `Nt=Nv=Nm=N=10` 需 1e11 次计算）。
- **两脉冲（bi-impulse）专用**：脉冲只加在每段两端，段内是 Lambert 弧，**速度由 Lambert 解唯一确定**，于是速度可从状态中剔除，状态降为 `(上一历元 t_last, 当前历元 t)` 的二维形式，复杂度 `O(Nt⁴N)`；再利用「同一 t_last 只影响当前 t 的状态」的时间匹配特性，降到 `O(Nt³N)`。
- 段代价（式 34）：`Δv_leg = ‖v_1 − v_2‖`，其中 `v_1` 是上一段 Lambert 弧在中间天体处的速度、`v_2` 是下一段 Lambert 弧在该处的速度——即**同一飞越历元处两段弧之间的速度差，合并为一个脉冲**。这与本项目 `MODEL_V3.md` §3.3「同刻脉冲先矢量合并再计费」一致。
- 附加约束的承载方式（GTOC11 案例，式 35）：把「飞越相对速度 ≤ 2 km/s」写成 `Δv = min(‖v_1 − v_flyby‖ + ‖v_flyby − v_2‖)` 并用圆锥曲线法解析求解，状态维数不变。这说明该框架可以吸收额外约束而不破坏状态定义。

### 3.4 自适应步长（论文 §IV.E.3）

「用大步长先得到粗略轨迹，然后在它附近用更小步长、更窄范围反复做 DP」的管道式细化。论文**明确承认它牺牲了全局最优性保证**，属于实用加速手段。两个关键参数是初始步长与管道范围。

### 3.5 论文算例

GTOC4 脉冲版本（沿用冠军的 48 飞越序列，末端交会）：

| 步长 (天) | 固定步长 ΔV (m/s) / 用时 (s) | 固定+自适应 ΔV (m/s) / 用时 (s) |
|---|---|---|
| 32 | 228,369.5 / 0.311 | 25,210.4 / 12.428 |
| 8 | 67,588.0 / 17.148 | 25,210.4 / 28.249 |
| 2 | 31,350.8 / 1,045.323 | 25,210.4 / 1,057.501 |
| 1 | 27,002.8 / 8,396.453 | 25,210.4 / 8,411.756 |

论文强调：即使步长降到 1 天，固定步长结果仍显著偏离最优值，说明问题高度非线性、局部极点多。最终比冠军省 20.2 kg 燃料。

## 4. 开源代码实际实现核对（论文 ≠ 代码）

我逐个文件核对了实现。以下均为代码事实，`文件:行号` 可查。

### 4.1 顺序是硬编码的，不是搜出来的

- `code/src/GTOC4_Problem.cpp:173-207` `chimpionship_result()` 把 GTOC4 冠军的 49 个天体编号与历元直接写在源码里，并把 `Sequence_gtoc4[0]` 置为 `-3`（地球）。
- `code/src/main.cpp:27-40` 取出该序列后调用 `DP_flyby_Lambert_iter(...)`。**全程没有任何顺序搜索**；GTOC11 分支同理，遍历冠军给出的若干条母船序列。
- 论文摘要/结论也只声称「under a given sequence」。顺序搜索在其姊妹论文（参考文献 [15][31][41]，多树搜索/连续交会）中，不在本仓库。

### 4.2 历元网格以冠军解为中心，不是从零开始的全局网格

`code/src/DP_flyby_2impulse_user_function.cpp:16-53` `possible_t_values`：

```cpp
t_min = T_sequence.front(); t_max = T_sequence.back();   // 冠军解的时间跨度
t_mid = (t_max + t_min) / 2.0;
t_min = t_mid - 5.0 * Year_GTOC4 * 86400.0;              // ±5 年
t_max = t_mid + 5.0 * Year_GTOC4 * 86400.0;
t_step = (t_max - t_min) / (T_sequence.size() - 1);
t_center = t_min + (stage + 0.5) * t_step;               // 每阶段一个中心
// 实际取值：t_center + i*step_t，i ∈ [-num_t/2, num_t-num_t/2)
```

即：**每阶段的历元窗口围绕冠军解在该阶段的时刻生成**。配合 `GTOC4_Problem.h:39-40` 的 `step_t = 32*86400`、`num_t = 31`，第一次「全局」DP 只在 31 个 32 天间隔的点上取值。

**这条对我们是硬约束级的提醒**：论文的全局最优性是相对这个离散网格（P2）而言的；网格本身被冠军解锚定。CTOC14 没有可用的参考解，粗网格必须由我们自己的启发式生成，此时「全局最优」的成色取决于粗网格是否覆盖了正确盆地。

### 4.3 段代价、剪枝与 GTOC4 专属写死项

`compute_rv_dv`（同文件 :112-150）：

```cpp
compute_v_nominal(id_departue, id_now, last_state.t, state_t, rv_departue, rv_arrival);
V_Minus(dv_vector, rv_departue + 3, last_state.rv + 3, 3);   // 当前历元处两段弧的速度差
dv = V_Norm2(dv_vector, 3);
total_dv = last_state.total_dv + dv;
```

写死在里面的 GTOC4 约定（**均须删除**）：

- `:129-136` 若当前是首段：`dv = max(0, dv − 4000.0)`——**允许 4 km/s 的免费 C3**（发射能量不计费）。
- `:138-146` 若当前是末段：额外加 `‖v_target − v_arrival‖`，即**末端按交会处理**。

`check_t`（同文件 :216-264）：相邻飞越间隔 `< 1 天` 或 `> 1 年` 直接返回 false；GTOC11 分支另有「不超过该目标的最大允许时刻」约束。**本题单段典型长度是数小时**，这条会直接砍掉绝大多数解。

### 4.4 Lambert 求解

- `LambEval`（`code/include/Lambert.cpp:320-369`）：先按最小能量椭圆算 `am`（:335），得最大可能圈数 `Nmax = floor(t / (2π√(am³/μ)))`（:338），然后 `n = 0..Nmax` 穷举圈数 × 2 个分支（:339-341），取 `dv0+dv1` 最小者（:350-365）。
- 分支选择准则是**该段两端脉冲之和最小**，而 DP 实际计费的是「本段出发端脉冲与上一段到达端脉冲之差」。也就是说，Lambert 圈数/分支的选择准则是启发式的，属于论文 `g̃_k` 近似误差 `ε_k` 的一部分，不破坏 DP 自身的一致性（同一 `(t_last,t)` 的分支是确定的），但它不是 DP 目标意义下的最优分支。**迁移时这是一个可以改进的点**。
- 单位：GTOC4 分支在 m / m/s 下计算（`*1000.0` 转换见 `GTOC4_Problem.cpp:44`）；`Constant.h:24-26` 给出 `muEarth`、`Re`、`J2`，但 **GTOC4/GTOC11 全程只用日心二体，代码里没有任何 J2 传播**。

### 4.5 DP 主体与支配剪枝

`code/src/DP_flyby_2impulse.cpp:46-134`（主版本）与 `:235-338`（细化版本结构相同）：

- 外层遍历当前阶段候选历元 `t`；内层把上一阶段状态按 `t_last` **分组**（`fabs(t - t_previous) > 1e-5` 判分组边界，:72 / :276）。
- 组内先按 `last_state->total_dv < min_total_dv` 剪枝（:83 / :287，注释声明「不影响最优性」），只为可能改进的状态调用一次 Lambert（`compute_rv_dv`），对同一 `(t_last, t)` 只保留累计 ΔV 最小的状态并 `push_back`（:104-107）。
- 回溯靠 `pre_state` 指针链（:173-185），指针指向上一阶段已停止增长的 vector，外层 `dp_state_all_stages_flyby_lambert` 只在开始时 `resize(Sequence_N)`，因此**指针不会因重分配失效**（我专门检查了这一点，未发现论文级 bug）。
- 阈值 `max_dv_threshold` 剪枝（:104）同样声明不影响最优性。

### 4.6 自适应细化

`code/src/DP_flyby_2impulse.cpp:389-399`：

```cpp
if (step_t > 100.0)
    DP_flyby_Lambert_iter(sequence, total_dv, result, false, "",
                          total_dv + 1.0e-3, step_t / 2.0, t_range / 2.0, false);
```

细化run 的网格改为以**上一次解的历元为中心**、`±t_range/2` 范围内、`step_t/2` 间隔；同时把阈值收紧为 `上一次总 ΔV + 1 m/s`，即每层细化都**不会变差超过 1 m/s**，是单调改进。递归到 `step_t ≤ 100 s` 停止（源码注释称 100 s 对结果影响小于 1 cm/s）。从 GTOC4 的 32 天起步到 100 s 约 15 层，每层每阶段网格点数恒定在 `2*12+1 = 25` 左右——这就是它能在 12 秒内跑完的原因。

## 5. 与 CTOC14 乙题（巡检轨道）的适配分析

### 5.1 题目与本项目模型的硬事实

- 35 颗中高轨故障卫星，10 天窗口（UTC 2035-01-01 12:00 → 01-11 12:00，864000 s），J2 动力学，脉冲机动。
- 巡检器**初始在近地轨道**：`a ∈ [RE+590, RE+610] km`、`e < 0.001`，轨道面与相位自由设计。
- 有效飞越：位置差 `≤ 1 km`；每目标只计一次；全程瞬时高度 `≥ 200 km`。目标函数先最大化访问数，再最小化 `ΔV/B`。
- 目标集不是单一轨道带。按 `data/ctoc14b_targets.csv` 统计：`a ∈ [14441, 42165] km`、`e ∈ [0.0003, 0.694]`、`i ∈ [0.12°, 63.48°]`，含近赤道 GEO、倾斜 GEO、GPS 型 MEO（a≈26560 km, i≈55°）、低轨 MEO（a≈14441/16730 km）与临界倾角 HEO（i≈63.4°, e 0.46-0.69）。**是跨轨道带的巡检巡游，不是单一小行星带内巡游。**

### 5.2 能对上号的部分

| 论文设定 | CTOC14 | 判断 |
|---|---|---|
| 飞越=位置重合、速度自由 | 距离 ≤ 1 km、无速度匹配 | **同构**（我们的判据是论文精确约束的松弛，只会更容易） |
| 同一历元两个脉冲矢量合并计费 | `MODEL_V3.md` §3.3 同刻脉冲先合并再计费 | **完全一致，可直接复用状态与计费定义** |
| 状态只保留 `(t_last, t)` | 若限定「脉冲只在飞越历元施加」 | 成立；但 V3 当前是自由机动（脉冲可在任意时刻），需作为**受限搜索层**而非全模型 |
| 给定顺序 → 全局最优历元 | V3 的顺序由搜索决定 | **需外挂顺序搜索**（论文不含） |
| 段代价是任意可计算的 `g̃_k` | 我们可用 J2 修正后的段代价 | 框架上兼容，代价是计算量 |
| 误差上界 `N·ε_max` | 可用于报告「离散化造成的偏差量级」 | 可作为口径工具，不是竞赛约束 |

### 5.3 对不上的部分（迁移限制）

1. **两体 vs J2**。代码全程二体。我的数量级估算（解析，非实验）：J2 摄动加速度 `≈ 1.5·J2·μ·Re²/r⁴`，在 GEO 半径约 `8.3e-6 m/s²`、MEO 半径约 `5.3e-5 m/s²`。数小时的单段内，自由积分位置偏差约 2.6 km（GEO）～17 km（MEO），**远超 1 km 判据**；但折算到速度只有 0.1～0.7 m/s/段，36 段合计约 10～25 m/s，相对 6 km/s 量级约 0.4%。**所以：二体 DP 的成本是可用的代理，二体弧本身不是可用轨迹；每段必须 J2 微分修正，最终仍走原脉冲独立验收。**
2. **时间网格需要重造**。代码的历元窗口锚定在 GTOC4 冠军解上（§4.2）。CTOC14 没有参考解可锚。
3. **`check_t` 的 [1 天, 1 年] 段长限制**与本题「数小时一段、总共 10 天」完全冲突，必须替换为本题的段长与 200 km 高度可行性筛。
4. **GTOC4 专属的免费 4 km/s C3 与末端交会**必须删除。本题初始轨道是受约束的近地圆轨道（a 被限死、面与相位自由），首段代价不是自由的 C3，而是一个受约束的离轨机动。
5. **顺序维度不在论文里**。35! 的顺序搜索必须由我们自己的机制承担；DP 只能作为「给定顺序的时序求解器/评估器」被调用。
6. **脉冲只在飞越历元 = 受限类**。V3 的正式模型允许任意时刻机动（`MODEL_V3.md` §3.2-3.3）。因此 DP 解是**该受限类内**的最优，不是全模型的下界，也不是全模型的上界。它可以作为高质量 warm start / 结构提案，不能替代自由机动层，也不能作为「已排除更优解」的证据。
7. **J2 下的多圈分支**。MEO/GEO 段在数小时里通常不足一圈，但离轨段与跨带转移可能有多圈机会；代码的多圈枚举准则（两端脉冲和最小）与 DP 计费口径不一致（§4.4），迁移时应改为与 DP 状态一致的准则或全分支保留。

### 5.4 与本项目现有实现的关系

- 项目已有 `src/+ctocscreen/chooseBranchesDP.m`——一个「每条腿预先枚举 Lambert 分支、再对分支链做 DP」的实现（V1 遗留）。它与 Zhang 的差别正是关键：**它把历元当枚举结果，Zhang 把历元当 DP 状态**，因此 Zhang 能在历元空间上给出最优性，而 `chooseBranchesDP` 只能在给定分支集合内选链。
- 项目已有二体 Lambert：`src/+ctocscreen/private/lambert_izzo_gooding.m`（来源 Rody Oldenhuis FEX-Lambert，提交 `f220826e…`，BSD-2，见 `LAMBERT_SOURCE.md`）。**DP 的段代价可以直接调用它**，不需要引入任何新依赖或 C++ 组件。
- 项目已有 J2 传播、连接修正、原脉冲独立验收（`v3Verify`、`v3Restore`、`v3ConnectControls` 等）。DP 的输出可以走同一条验收链。

## 6. 可迁移机制分级

### A. 可直接借鉴（低风险）

- **A1 支配剪枝**：同一 `(t_last, t)` 只保留累计 ΔV 最小的状态。在「脉冲只在飞越历元」的受限层内这是保最优性的剪枝，可用作束搜索的合法状态合并规则（注意：V3 的自由机动层状态含 visited 集合与真实 r,v，不能照搬）。
- **A2 回调式问题接口**：`possible_t_values / compute_rv_dv / check_t / print_optimal_path` 四函数把问题相关部分与 DP 主体完全解耦。这个分层方式值得照抄——我们的版本对应「历元候选生成 / J2 段代价 / 高度与判据筛 / 结果导出」。
- **A3 单调细化**：每层细化把阈值收紧为「上一层总 ΔV + 小量」，保证细化不会变差；步长与管道范围同步减半，每层网格点数恒定。可以直接作为时序层的精修调度。

### B. 需改造后使用（中风险，建议先做最小验证）

- **B1 给定顺序的两体两脉冲历元 DP**（核心）。改造清单：删除免费 C3 与末端交会；`check_t` 换成本题段长/高度可行性；历元网格由我们自己的启发式生成（不能用冠军解锚定）；段代价用现有 Izzo/Gooding Lambert；输出交 J2 微分修正。
- **B2 误差上界口径**：把 `N·ε_max` 作为「离散化 + 二体近似」的误差量级报告项，与真实 J2 复核结果分开记录。不要把它写成竞赛条件或最优性证明。
- **B3 多圈分支准则**：把「两端脉冲和最小」改成与 DP 状态一致的分支保留策略（例如按到达端速度也保留若干分支），或直接全分支入状态再做支配剪枝。

### C. 不可迁移

- GTOC4/GTOC11 专属的免费 C3、末端交会、年尺度段长、以冠军解为中心的时间网格。
- 「给定顺序」这一前提本身：不能声称该方法能解 CTOC14 的顺序搜索问题。
- 论文的全局最优性结论：在本题下它只在「两体 + 脉冲仅在飞越历元 + 离散历元网格」三重近似内成立，且网格必须是中性的（不锚定任何已知解）。

## 7. 计算可行性实测（临时微基准）

**假设**：Zhang 式 DP 在 MATLAB 内是否量级可行。
**做法**：把已入库的 `lambert_izzo_gooding.m` 复制到 `tmp/bench/`，对 20000 组随机 MEO→GEO 端点几何、2–11 h 时长、0 圈分支计时（`tmp/bench/bench_lambert_dp.m`）。
**结果**：20000 次调用 0.128 s，**6.4 µs/次**，0 失败。按最坏界 `Nt³N` 外推：

| Nt | 段代价调用数 | 估计耗时 |
|---|---|---|
| 50 | 4.4e6 | 0.01 h |
| 100 | 3.5e7 | 0.06 h |
| 200 | 2.8e8 | 0.50 h |
| 400 | 2.2e9 | 3.99 h |

**能支持什么结论**：单次 Lambert 不是瓶颈，配合 A1 剪枝与 A3 管道细化，MATLAB 内做 35 段 DP 在算力上可行。
**不能支持什么结论**：这不代表完整 DP（含目标星历、多圈枚举、J2 修正、候选生成）就是这个耗时；也不能说明 DP 的解一定比现有搜索好。
