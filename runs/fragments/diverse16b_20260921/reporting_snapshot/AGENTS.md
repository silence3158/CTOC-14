# CTOC14 项目必须遵守的约定

本文件适用于 `D:\CTOC-14\simulation` 及其子目录。项目根目录固定为 `D:\CTOC-14`。实施规划、求解器或验证相关工作前，必须阅读 [docs/MODEL.md](docs/MODEL.md) 与 [docs/MODEL_V2.md](docs/MODEL_V2.md)。前者保留正式条件与 V1 历史模型，后者为用户于 2026-09-21 要求重新建模的当前 V2 轨迹结构与仿真设计；V2 文档不代表功能已实现。

- 编程语言固定为 MATLAB。主程序、动力学、求解、搜索、复核和测试使用 `.m` 文件，不引入 Python 运行依赖。采用 `+ctocscreen` 包组织代码，数值使用 `double`，状态与检查点使用 MAT 文件。工具箱能力在实现前核验；无并行工具箱时保留串行运行方式，不默默更换算法。
- 用户于 2026-09-21 指示先用简单动力学做大批次筛选，不进入 ATK 仿真，不考虑 B，只以总 ΔV 为目标。实施前同时阅读 [docs/BATCH_SCREENING.md](docs/BATCH_SCREENING.md)。

- 本阶段不启动或连接 ATK；后续正式动力学和场景交付约定保留，在用户推进相应阶段后执行。离线读取原始文件进行数据核验不属于 ATK 仿真。
- 算法中的圈数上限、时间网格和正时长下界是可配置搜索近似，不得写成赛题限制。导出精英须按实际状态逐段重放并重算 ΔV，不能只使用名义分支 DP 成本。当前代码的搜索 archive 与独立复核 export_archive 必须区分；只有固定原脉冲连续独立积分通过的候选可写为新的 elite.mat。
- BATCH_SCREENING.md 中的设计参数仅是起步建议。已实现范围以 docs/BATCH_IMPLEMENTATION.md 为准，实际运行证据以 docs/BATCH_RESULTS_20260921.md 为准；不得将未实施的设计或未测试的配置当作功能和成绩。
- V2 首轮固定初轨 S1/S2 实验见 docs/V2_IMPLEMENTATION.md 和 docs/V2_PILOT_RESULTS_20260921.md。后续全局束搜索、自由初轨及通用多脉冲多目标片段实现与小规模结果见 docs/V2_ADVANCED_ALGORITHMS.md；必须按各阶段实际范围报告，不得把接口能力、合成测试成功或未成功的真实数据试验说成已得到更优完整任务。

- 用户要求大批次具备真正的多起点和跳出能力：不得把相同精英附近更换 RNG 种子称为充分探索新区域。归档各任务实际初始访问顺序、时间、初轨与种子差异；历史最好解与允许上坡的工作解分开保存。用户终止或调整的批次按已完成/中断/未启动如实统计。

## 模型不可擅改

- 主问题：一艘巡检飞行器在不超过 10 天内飞越全部 35 颗目标，在全部正式约束满足时最小化总 ΔV。
- 正式评分严格按访问数优先、同访问数时 F2 次之；禁止随意加权替代，禁止沿用旧代码的 ΔV—耗时 Pareto 目标。
- V1 保留初始自然滑行加 35 段串联单脉冲飞越及 42 个连续变量的历史实现。V2 按 MODEL_V2.md 将机动与访问解耦：机动时刻、脉冲矢量和机动拓扑可优化，允许访问前后自然滑行、两个访问之间机动，以及一条自然弧访问零个、一个或多个目标。不得将 V1 的固定槽位数或事件绑定限制强加给 V2。
- V2 保留完整初始轨道 6 自由度，以真实脉冲时间表和访问事件表达轨迹；机动次数、片段模板及分支由外层搜索管理。总任务时间不强制用满 10 天，计算上的机动数上限必须标为搜索近似。
- 初始 a0 位于 [RE+590, RE+610] km，0 <= e0 < 0.001；初始轨道面与相位可设计。不得把正式问题固定为 600 km 圆轨道。
- 题目没有交会速度匹配、服务停留、返航、多航天器、总 ΔV 上限、单次脉冲上限或脉冲次数上限。禁止从参考代码带入这些限制。
- 进一步改变已确认的轨迹结构、任务目标、自由度或硬约束，必须先与用户讨论，并同步更新当前模型文档及本文件。V1 MODEL.md 保留版本迁移说明；等价变量编码、搜索算法和数值方法可在模型范围内自行实现并记录。

## 状态与动力学

- 飞越后必须传递巡检飞行器的真实位置和到达速度。严禁重置为目标卫星速度，严禁通过重置位置消除数值残差，严禁添加未要求的末端交会脉冲。
- 中间脉冲为下一段所需出发速度减去上一段实际到达速度。总代价为所有实际脉冲向量模长之和。
- V2 自然飞越不触发脉冲；实际脉冲施加在显式机动时刻。近零连接残差不能直接证明可删脉冲；单脉冲多目标片段必须以真正删除中间脉冲后的自然传播复核。片段改动后须重新验证后缀连接与完整任务净成本。
- V2 使用独立接口版本 fragment_schedule_v2、dynamics_id=two_body 和 runs/fragments 输出目录；不得与既有 two_body_screen_v2 实现标识混淆，不覆写 V1 精英或以 V1 固定 35 段评价器冒充 V2 验证器。
- 转移分支影响后续到达状态。不得把逐段贪心最小 ΔV 宣称为序列最优；分支裁剪与圈数限制必须作为可配置搜索近似记录。
- 内部物理单位统一为 km、s、rad、km/s；历元为 UTC 2035-01-01 12:00:00，任务时限 864000 s。角度、时间尺度和坐标系转换必须显式处理。
- 正式动力学仅中心引力与 J2，参数及参考系与竞赛版 ATK/EGM96 对齐。禁止把近圆交会估价器或 J2 平均传播当作最终验证模型。

## 数据与验证

- 目标入口为 `data/ctoc14b_targets.csv`，原始依据为 `D:\CTOC-14\problem\ctoc14乙题\CTOC14B.atk`。核验 35 个唯一目标、历元、单位、坐标系和提取精度；优先使用与原场景一致的笛卡尔状态传播。
- CSV 的速度分量单位为 km/s，而 `|v| (m/s)` 是 m/s；轨道角度列为度。不得混用真近点角与平近点角，也不得默认其根数为平均根数。
- 必须检查全部目标的实际接近事件；距离 <= 1 km 为有效飞越，同一目标只计一次。计划序列长度不能证明访问数。
- 高度 >= 200 km 约束覆盖从初始历元到任务结束的全过程，包括初始滑行和段内部；不得仅检查端点或仅凭稀疏采样宣布通过。
- 求解失败、非有限状态或未到靶必须显式标记。不得以零成本或有限惩罚值掩盖后再报告为可行解。
- 区分搜索近似、本地动力学复核、竞赛版 ATK 验证。未实际执行并通过的验证不得声称通过；RunMCS 成功返回不能单独证明可行。
- 固定种子或记录随机状态、配置、分支裁剪、容差及运行结果，以支持复现。调试时固定变量或增加算法边界必须显式标注为受限实验。
